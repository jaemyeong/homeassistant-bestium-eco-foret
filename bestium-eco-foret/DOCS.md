# BESTIUM Eco-Foret Wallpad

EW11 게이트웨이를 통해 월패드의 RS485 회선을 읽고, 실측으로 확인된 조작만 내보냅니다.
웹 페이지와 Home Assistant 엔티티 두 가지 표면을 제공합니다.

## 구성

네 가지만 설정합니다. 나머지 값은 전부 이 버스에서 측정된 상수이며 소스에 근거와 함께
적혀 있습니다.

| 항목 | 설명 |
| --- | --- |
| `ew11_host` · `ew11_port` | EW11 게이트웨이의 주소와 포트 |
| `transmit_enabled` | 송신 허용. 꺼져 있으면 어떤 표면에서도 기기를 조작할 수 없습니다 |
| `transmit_user_id` | 조작을 허용할 Home Assistant 사용자 ID. 없으면 송신이 전부 막힙니다 |
| `mqtt_commands_enabled` | Home Assistant가 MQTT로 월패드를 조작할 수 있게 합니다 |

MQTT 브로커의 주소와 계정은 Supervisor가 알려 주므로 입력하지 않습니다. Mosquitto 애드온이
설치되어 있지 않으면 조용히 대기하다가 1분마다 다시 확인합니다.

## MQTT 엔티티

기기 하나에 엔티티 열여섯 개가 붙습니다.

| 엔티티 | 종류 | 비고 |
| --- | --- | --- |
| 등 1·2·3 | `light` | |
| 난방 1~4 | `climate` | 5~40 °C |
| 가스 밸브 | `valve` | **닫기만 가능합니다** |
| 일괄소등 | `switch` | **기본 비활성** |
| 승강기 층·진행 방향·호출 상태 | `sensor` | |
| 승강기 상행·하행 호출 | `button` | 취소 불가 |
| 세대현관 문열림 | `event` | |

일괄소등만 비활성으로 배포되며, 기기 페이지에서 직접 켜야 나타납니다.

# 반드시 알아야 할 네 가지

## 1. 난방 목표 온도를 쓰면 그 존이 켜집니다

네 존 여덟 번 모두 그랬습니다. **야간 설백 자동화가 정확히 그 호출을 합니다.**

MQTT도 웹 페이지도 월패드와 똑같이 동작합니다. 꺼져 있는 존에 목표를 쓰면 **그 존이
켜지고**, 2초쯤 뒤 폴링이 `heat`를 보고합니다. Home Assistant는 사실을 말하지만 그것이
의도하신 바가 아닐 수 있습니다.

애드온이 이것을 막았던 적이 있으나(0.5.2) 되돌렸습니다. 막으면 MQTT에는 실패를 알릴
통로가 없어 조용히 무시되고, 같은 기기가 두 표면에서 다르게 반응하기 때문입니다.

**꺼진 존의 목표를 자동화에서 바꾸실 계획이라면 그 존이 켜진다는 것을 전제하십시오.**
켜져 있는 존의 목표를 되돌릴 때는 **목표를 먼저 되돌리고 그다음 끄는 순서**여야 합니다.

## 2. 문열림은 집 안에서 월패드 버튼을 눌렀을 때만 발생합니다

비밀번호 출입도, 열쇠도, 초인종도 이 회선에 나타나지 않습니다. 벨·통화·영상은 전부 서브폰
회선에 있고 그 회선은 아직 측정되지 않았습니다.

**"누군가 귀가함" 자동화를 이 신호에 걸면 안 됩니다.** 그런 용도가 아닙니다.

## 3. 승강기 호출이 "미확인"으로 끝나는 것은 정상입니다

호출 등록은 1.6초쯤 걸리고, 상태 스트림은 **건물 전체의 대기 중인 호출**을 나릅니다.
이웃이 같은 방향 호출을 이미 걸어 두었다면 우리 호출이 등록되었는지 구조적으로 판정할 수
없습니다.

**자동화에서 `repeat`으로 감싸지 마십시오.** 한 번 누르면 이미 최대 세 프레임이 버스에
나갑니다. 취소 기능은 이 건물에 없습니다.

호출 버튼은 활성 상태로 배포되므로 자동 생성되는 개요 대시보드에 조명 토글 옆으로 PRESS
타일 둘이 그대로 놓입니다. **오조작을 막으려면 대시보드에서 그 타일에 `confirmation:`을
거십시오.** MQTT 자동 발견은 확인 절차를 표현할 수 없어 애드온 쪽에서 넣을 방법이 없습니다.

## 4. 음성 도우미에 노출하면 가스가 위험합니다

`"‹구역› 전부 꺼"`라는 발화가 `HassTurnOff → close_valve`로 이어져 **밸브 이름을 말하지
않아도 잠깁니다.** 밸브는 사람이 현장에서 손으로 열어야 합니다.

**설정 → 음성 도우미에서 가스 밸브 엔티티 하나만 노출에서 제외하십시오.** 대시보드와
자동화에서는 그대로 쓸 수 있고, 발화로만 닿지 않게 됩니다.

`"전부 켜"`는 승강기 호출 버튼을 누릅니다. 그것도 노출에서 빼거나 대시보드 타일에
`confirmation:`을 거는 편이 좋습니다.

# 아직 측정되지 않은 것

## 일괄소등 해제가 무엇을 복원하는지 모릅니다

현관의 일괄소등 스위치는 **월패드가 닿지 못하는 다른 방 조명에 이르는 유일한 경로**입니다.
확인된 것은 프레임의 한 바이트가 걸림과 풀림 사이를 오간다는 사실이고, 송신은 **총 2회**뿐
입니다.

**해제가 그 방들을 복원하는지는 측정된 적이 없습니다.** 복원하지 않는다면 걸기는 그
방들에 대해 가스 차단만큼 되돌릴 수 없습니다.

그 방들이 보이는 자리에 서서 해제를 한 번 보내면 이 공백이 닫힙니다.

## MQTT 명령은 브로커에 발행할 수 있는 누구에게나 열립니다

MQTT PUBLISH는 호출자 신원을 담지 않고, 이 애드온의 권한 검사는 설정값 일치 검사입니다.
웹 페이지는 Home Assistant 로그인과 CSRF 토큰을 요구하지만, MQTT 명령은 브로커가 요구하는
것만 요구합니다.

**브로커가 Home Assistant 호스트 너머로 열려 있다면 `mqtt_commands_enabled`를 켜지
마십시오.** 읽기 전용 엔티티만으로도 자동화에서 상태를 읽는 것은 됩니다.
